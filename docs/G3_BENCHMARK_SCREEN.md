# G3 预注册：LSFlow 五个公开 benchmark 的筛选

日期：2026-11-05。本文在运行任何筛选代码之前写定。上层设计见 [SOLVER_LOCALIZATION_DESIGN.md](SOLVER_LOCALIZATION_DESIGN.md)。

本筛选不训练任何模型，也不解除 G0.5 “不进入 G1/G2” 的决定。它只回答：方法能落到哪些 benchmark 上，在哪些上值得主张 diffusion。

## 五个任务

| 任务 | 规模（上游命令） | 动作 |
|---|---|---|
| Scheduling | N=40, B=10, H=20, 10 工人, 5 时段 | 选患者并分配两条工人-时段边 |
| Routing | N=40, B=10, H=20, T=20 | 从 source 出发的闭合路线，访问点中选至多 B 个 |
| Assignment | N=40, 10 工人, H=20 | 带容量的工人-患者分配 |
| Intervention | N=40, A=20, B=10, H=20 | 选至多 B 个干预。上游 A=40 的构造会报错，沿用仓库端口的 A=20 |
| STI | 真实接触网络，frontier + 预算 | 从 frontier 中选至多 B 个节点 |

实例由上游代码生成（只对 Gurobi、绘图依赖打桩），种子 0、1、2。Intervention 用仓库的 NumPy 端口。

**已知限制：** STI 的原始 TSV 和图缓存都不在本地，也不在服务器上；只有拟合参数。没有数据就无法跑 Q1，此项记为“阻塞”，不用合成图代替。数据需要你在 ICPSR 申请，我不会代为注册。

**运行前已知的结构事实：** Scheduling、Routing、Assignment 共用同一个多状态 RMAB：各臂独立转移，奖励逐臂相加。因此，若后续策略不依赖状态，Q 对 a 严格可加，非线性只能来自依赖状态的后续策略。这使“Q 高度线性”成为这三个任务的主要风险。

## 三个问题

### Q1：Q 对动作的非线性有多强

- **Q：** 从状态 s 执行 a，之后按贪心策略滚动到 H，用蒙特卡洛估计。贪心策略每步最大化逐臂期望增益之和，由各任务的 solver 求解（Intervention 取 top-B）。
- **状态：** 每个实例取 h=0 和 h=10，由贪心策略滚动得到。
- **动作集：** `random`：上游的随机可行动作，150 个。`near`：在贪心系数上加噪声（标准差等于系数标准差）后求解，150 个；这更接近策略实际所在的区域。
- **估计：** 每个动作 8 次滚动。5 折交叉验证的线性回归 R²（ridge 1e-6），除以 split-half 信度（Spearman–Brown），上限截到 1。信度低于 0.5 或不重复动作少于 60 个时，该格记为不可用，不计入平均。
- **控制：** 后续策略换成随机动作时，RMAB 三个任务的 Q 严格可加，校正 R² 应接近 1。这用来校验流程。

判定用**较低的那个动作集**的实例平均校正 R²：

| R² | 含义 |
|---|---|
| ≥0.95 | 高度线性：对数线性预计够用，不作 diffusion 主张 |
| 0.90–0.95 | 边界：需要对数线性对照，暂不主张 |
| <0.90 | 非线性足够，可作主张候选 |

0.9 沿用 G0.6 A4，0.95 按量级定，都不是统计检验。

### Q2：`M_A` 能否精确计算

在扩展动作上计算，并在小实例上用枚举校验（误差 ≤1e-8）：

| 任务 | 扩展动作 | 方法 |
|---|---|---|
| Intervention、STI | a | 选 k 个的 DP（STI 只测计算量，用合成 mask，已标明） |
| Routing | 路线 + 拉取时刻 | (时刻, 节点, 已拉取数) 分层前后向。同一节点可重复拉取，a 取 OR，解仍可行，但线性得分会重复计算 |
| Assignment | x，每臂至多一个工人 | 剩余容量张量 DP。上游 MIP 允许重复分配，但不改变可行的 a 集合 |
| Scheduling | (a,x) | 已用工人-时段掩码 + 已选数的 DP |

分级（单线程，单次精确均值）：

| 级别 | 条件 |
|---|---|
| 快 | ≤50 ms |
| 慢 | ≤10 s 且 ≤64 GB |
| 不可用 | 超过任一上限 |

Assignment 只运行前向，均值时间按前向 ×3 估计，已标明。Scheduling 的掩码 DP 超限只说明**这种做法**不可用，不证明问题本身难解。

**通用近似：** `M̃(η) = (1/K)ΣSolver(η+Gumbel)`，K=32。小实例（Scheduling 20/5/5，Assignment 20/5）上对照精确值，a 比特的平均绝对误差 ≤0.05 记为可用。η 的尺度取 σ∈{0.5,1,2} 的高斯。结果按最差的 σ 判定。

### Q3：solver 成本与可行性

- 200 个高斯系数，单线程，HiGHS（服务器无 Gurobi）。解得 p95 ≤100 ms 算通过，沿用 G0.6 A2。时限 2 秒，超时记录。
- Routing 同时测 DP 和上游 MILP，并报告 DP 相对 MILP 的值差。滚动中用 DP。
- 32 个随机系数上，检查上游 `solve_from_coeffs` 风格的 top-B 解码（Scheduling、Routing）放回 MILP 后是否可行。只报告。

## 判定

| 结果 | 条件 |
|---|---|
| **可主张** | Q1 R²<0.90，`M_A` 为快/慢或近似可用，solver 通过 |
| **可覆盖但不主张** | Q1 R²≥0.90，其余同上。作为基线比较运行，对数线性必须同跑 |
| **阻塞** | 缺数据，或 `M_A`、solver 均不可用 |

**对论文定位的影响（沿用 G3 原条件）：** 如果 4 个可测任务全部 R²≥0.90，就不能在这些公开 benchmark 上主张非线性 diffusion。论文定位改为“带硬约束的最大熵组合 RL”，或者把 diffusion 主张限定在自建的非线性任务上。这需要你决定。

## 边界

Q 来自贪心后续策略，不是训练后的 critic，也不是最优 Q；优秀策略下的非线性可能不同。每个任务只有 3 个实例、2 个状态。R² 高不等于最优动作处局部线性很好，`near` 动作集只能部分反映这一点。不按结果调整阈值；实现中若必须修改本文，先记录改动和原因，并标明当时已看到哪些结果。

## 执行

wflow-server，单 controller，worker 名为 `llmagent`，不可变快照，单线程绑核，不动无关进程。scipy 装在快照自己的目录。记录配置、源码哈希、PID、主机和退出状态；已有输出不覆盖，失败不静默重试。预计超过 8 个 worker 跑 8 小时时，先停下问你。

## 运行前的改动记录

改动时已看到的内容：只有实例 0 的冒烟输出（Q1 每格 30 个动作、4 次滚动，R² 不可用）、solver 耗时、枚举校验。没有看到任何可用的 R² 结果。以下改动不依据 R² 做出。

1. **Routing 拆成两个变体。** 上游 MILP 含 `unrolled[j][j][t]` 自环变量，它们计入访问但不计入路径长度，形成不走路也能“访问”的幽灵流。实例 0 上，16 组 top-B 动作放入发布版 MILP 全部可行；禁用自环后 15 组不可行。上游训练解码又是 top-B，`step` 只检查预算。因此发布版实际上是选 B 个的问题。
   - `routing_published`：选至多 B 个，solver 为 top-B。对应已发表结果实际解决的问题。
   - `routing`：论文所述的严格路线，MILP 禁用自环。
2. **严格路线的 solver。** 原定的 walk DP 会重复计分同一节点，实例 0 上值约为 MILP 的 1/4–3/5，不可用。严格 MILP 用 HiGHS 要 3–12 秒，无法用于滚动。改用束搜索（宽度 200，按访问集合 top-B 正分计值）。在 20 个系数上对照严格 MILP（时限 20 秒）：平均值差 ≤5% 且 p95 ≤100 ms 记为 solver 通过；否则未通过，并如实报告。
3. **`M_A` 与 solver 的不一致。** 路线 + 拉取的 DP 在扩展坐标上仍是精确的，但节点坐标上的线性分数会被重复计算。可加奖励在扩展坐标上因此不再是线性的。Q2 仍按扩展坐标报告，判定时一并注明。
4. **公共随机数。** 随机转移噪声盖过了动作差异。同一次滚动编号的所有动作共用同一组转移均匀数和后续随机流，按滚动编号做 split-half。这只降低动作间比较的噪声，不改变 Q 的期望。滚动次数由实例 99 上的试跑确定，不用实例 0–2。
5. **Scheduling 的 top-B 只作信息。** 上游 Scheduling 走 MILP，top-B 不是它的解码方式。
6. **校正 R² 的算法。** 改动时已看到实例 99（预留试跑，不计入结果）h=0 上的 R²。公共随机数使噪声也近似可加，会被线性回归拟合，“R²÷信度”因而过度校正并顶到 1。改为两半交叉估计：`R² = 1 − cov(e_A, e_B) / cov(y_A, y_B)`，y_A、y_B 是两半滚动的平均 Q，e 是各自的 5 折交叉验证残差。两半噪声独立，协方差只留下真实信号。阈值不变，判定用这个值。原始 R² 一并报告。
7. **滚动次数改为 16。** 依据实例 99 的试跑（信度 0.84–0.91）和耗时。
8. **控制实验的读法。** 公共随机数下，随机后续策略的控制应使原始 R² 接近 1，判读用原始 R²；Intervention 的动作经 sigmoid 进入，不适用这一预期。
